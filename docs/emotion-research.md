# 情绪系统调研：别人怎么工程化的

> 目的是避免重复造轮子。调研了 AstrBot 生态里两个现成实现，重点是
> [BioCore](https://github.com/Johnhmzm/astrbot_plugin_biocore)（拟态生物情绪核心，v1.4.19）。

## 一、BioCore 的核心主张

它对自己的定位写得很克制：

> 这里的"拟态"指**行为层模拟**：模仿生物情绪系统的功能结构，不声称复刻神经元、内分泌或意识。

三条工程原则，直接回应了我们争论的两个问题：

| 它的原则 | 对我们的意义 |
| --- | --- |
| **状态更新是确定性的，LLM 不直接写状态** | 印证了「每轮调 LLM 评情绪」是小题大做 |
| **解释层是唯一把数值转成 LLM 可读文本的通道** | 情绪进上下文的唯一出口，不让模型碰原始数字 |
| **关闭 LLM 总结后仍能靠本地确定性逻辑运行** | 零 LLM 成本也能完整跑 |

它还默认 `llm_only_reply_summary: true`——**LLM 只用于回复和总结**，
`relationship_impression`、`insight`、`diary`、`humor_hint` 这些提案型功能**默认全关**。

## 二、状态维度：它比我们多三个

| BioCore | 本项目 | 差异 |
| --- | --- | --- |
| `valence` | `valence` | ✓ |
| `arousal` | ~~无~~（只有二维 affect 里有） | 我们有但没进五维 |
| **`dominance`** | ~~无~~ | **PAD 的第三轴，缺** |
| `social` | `sociability` | 同名不同义（它指社交驱力） |
| **`trust`** | ~~无~~ | **关系维度，按 user 维护** |
| `stress` | `stress` | ✓ |
| **`energy`** | `energy` | ✓ |

关键差异是 **`trust`（信任）**：它不是一个情绪，而是**按会话/用户维护的关系轨迹**，
和情绪分开（「关系：信任/亲近/冲突/修复 —— 冲突后通过修复动作回到稳定」）。

**这正是用户说的「针对某个人的好感度」**——它是一个独立的、按人累积的状态，
不能塞进「全局心情」里。

## 三、机制：认知评价用规则，不是 LLM

它模仿的是 OCC 评价模型，**四类参数化判断**：

```
相关性 → 利害 → 应对 → 归因  →  情绪变化
```

也做：情绪衰减与恢复（压力/能量/睡眠参与恢复速度）、稳态调节（能量/社交/安全/好奇的设定点）、
内感受（「累、渴、紧绷、想说话」）、趋近/回避/停顿、记忆巩固/遗忘/再激活、依恋与缺席。

全部是**可计算的状态**，不是每轮问一次模型。

## 四、我们对照下来该改什么

### 1. 情绪由 scene 写，self 只读（修正接线错误）

现在的错误：`self` 决策时写二维 `affect`，`scene` 回复时读它。
但 self 看不到完整对话，它写的是**事后想象**；scene 才是真实互动发生的地方。

BioCore 的做法是回复后评估（`observe(event, bot_reply)`），
`permits_proactive` 供外部读——**写和读分开，且写的人必须见过那一轮**。

### 2. 不用 LLM 算情绪，用认知评价规则

`±1~3` 的小量不需要一次完整 LLM 调用。用四类判断做规则：

| 判断 | 例子 | delta |
| --- | --- | --- |
| 相关性 | 被 @、被点名 | interest+, sociability+ |
| 利害 | 被夸 / 被骂 | valence±, stress± |
| 应对 | 能不能接上（接得漂亮/被问住） | dominance±, stress± |
| 归因 | 对方是故意还是无心 | trust± |

每条规则都能给出具象 reason，不需要模型编。

### 3. 加 `trust` 维度，按 user 维护

这是「对某个人的好感度」，和「我这会儿心情如何」是两件事：

```
情绪（按 scope）：我这个群这会儿什么状态
信任（按 scope+user）：我对这个人什么态度
```

冲突后通过「修复动作」回到稳定——BioCore 明确列了这一条。

### 4. 解释层用 telemetry，不是自然语言

BioCore 默认 `bc_prompt_mode: telemetry`——注入**紧凑数值**而不是一段自然语言描述。
这对省预算有意义：一段「我现在有点累但还挺想聊」可能 30 字，
而 `[BC] v:62 a:48 d:55 s:70 t:64` 只要 20 字且信息更密。

不过拟人化需要自然语言。折中：**默认给一句短的（不超过 20 字），需要细节时给数值**。

## 五、不打算照搬的部分

| BioCore 有 | 我们不做 | 理由 |
| --- | --- | --- |
| Dashboard（WebUI 面板） | 不做 | 用户明确说过不做 WebUI |
| 一次性人设编译成数值档案 | 不做 | 我们的人格是代码里的常量，不需要编译 |
| 向量检索 + 重排 | 不做 | 记忆层已用 IDF 词法，规模不需要向量 |
| 睡眠/饥饿/口渴等身体状态 | 不做 | 那是「生物拟态」取向；我们要的是对话情绪，不是养宠物 |
| 依恋与缺席 | 暂不做 | 需要长期数据才能验证，先不引入 |

## 六、结论

- **对**: BioCore 是这轮调研里最值的参考，它的三条工程原则直接回答了我们的两个争议点。
- **改**: 接线方向（scene 写 / self 读）、算情绪的方式（规则不是 LLM）、加 trust 维度。
- **不改**: 不引入生物拟态那一整套（睡眠、饥饿、依恋）——那是另一个产品取向。
