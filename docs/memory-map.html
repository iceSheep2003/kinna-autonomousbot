记忆机制总图

一条记忆从发生到被想起来，中间经过哪些环节 · 对应 src/memory/ 下的文件

01全景：一条记忆的一生

三个动词：写（发生的事怎么进库）、整理（夜里 Dream 怎么重构）、读（下次醒来怎么被想起来）。

02分层：一条记忆属于哪个场合

核心规则只有一句：向下看得到，向上看不到。在 A 群能读「通用」+「A 群」，读不到 B 群。

为什么不是「全隔离」。线上原版是跨群绝不可见，代价是同一个人换个群就变陌生人， 「他喜欢别人叫全名」这种跟群无关的事每个群都要重学一遍。 分层要解决的就是这个。

03整理：Dream 夜里的四件事

这是整套机制里唯一会「重构」记忆的地方，也是它最难讲清楚的部分。四项各管一件事，互不重叠。

04读取：一次注入里发生了什么

从「我要回忆」到「模型看到的那段文本」，中间有四次过滤。

05两个容易被忽略的特例

对话也要压缩

场景每次只读最近 20 条经验，更早的直接丢弃。群聊里这会断掉三样东西：还在继续的话题、没接住的话、之前开的玩笑。

所以把窗口外的旧对话压成「现场状态」——话题线、没接住的事、可接的梗、我说过什么。产物是可接着说下去的现场，不是摘要。

execution/scene-compaction.ts

遗忘必须可逆

归档不是删除：内容和证据都留着，只是不进默认上下文。

主动回想（memory.search）会连归档的一起翻，命中就恢复成 active。归档判断本来就可能出错——重要度标低了、那条恰好不常被问。一次归档等于永久丢失是不可接受的。

06文件地图

文件干什么关键约束
types.ts记忆与 Dream 的数据形状字段全部可选，兼容旧库
scope.ts作用域解析、可读集合、提升规则非法 scope 一律当 owner
access.ts读取前的统一验权检索前过滤，不靠提示词
ranking.ts + text.ts打分与字组相似度IDF 加权，分母用并集
render.ts渲染成给模型看的文本分 general / scoped；超长整条跳过
index-layer.ts索引结构、渲染、裁剪≤40 条 / ≤4000 字符；悬挂引用丢弃
promote.ts提升到通用层的判据与执行复制不移动；重复提升拦截
compact.ts + compact-service.ts合并重复记忆证据并集；原记录标 superseded
forget.ts + forget-service.ts归档冷掉记忆四条保护；可逆
dream.ts + dream-effects.ts回放整合 + 四项副作用回放决定记什么，副作用决定怎么组织
service.ts把以上串起来分池配额、scope 参数化
execution/scene-compaction.ts对话现场状态只保留影响接话的内容
这图里哪些是验证过的、哪些不是。
验证过：分层隔离、提升后跨群可见、压缩证据不丢、归档可逆、分场景索引分得开、IDF 改善排序、对话压缩出可用的现场状态。 用的都是线上真实数据（287 条记忆 + 两个真实群）。
没验证：长期跑下来索引会不会漂、四项全开时一次 Dream 的 token 成本、归档会不会误伤。 这些要接真实群聊跑一段时间才知道。
